# v0.1.0-rc.2 需求规格：可用的需求分析与用例产出闭环

**Status:** ready-for-agent

## 1. 发布目标

rc.2 的首要目标是让测试工程师能够完成一条可判断、可修改、可交付的主流程：

> 创建测试设计项目 → 选择多份需求资料 → 真实大模型分析 → 查看并确认需求表 → 生成、编辑、移除和导出用例表。

本版本不以继续扩展执行治理、复杂变更影响或完整报告为目标；这些能力不得阻塞主流程。

## 2. 用户与边界

- 用户仍是单一测试工程师，不新增账户、登录、多人协作或审批体系。
- 旧项目只能作为用户体验和验收结果的参考，不得复制其代码、Prompt、数据、页面、原始业务内容或未公开信息。
- 真实模型和 Mock AI 运行必须明确区分；Mock 不得伪装为真实分析。
- 来源不明资产和评估真值不得进入正常模型上下文。

## 3. 项目创建

创建或编辑测试设计项目时提供并校验：

- 必填：项目名称、测试对象、软件版本；必填标签使用红色 `*`。
- 可选：项目描述、需求资料默认语言。
- 软件版本保存于项目级上下文，并自动写入导出的每条用例；不与平台内部需求版本混用。
- 点击“保存修改”后显示绿色“✓ 已保存”，并显示保存时间；失败显示明确错误。

## 4. API Key 与模型服务

- 项目工作台提供供应商、模型、Base URL、API Key、连接测试和清除配置入口。
- 供应商下拉框预置 DeepSeek、硅基流动、Kimi、GLM；每个供应商提供对应的可选模型下拉列表。
- 提供“自定义供应商”模式；此时 Base URL 和模型名称由用户填写，模型名称使用文本输入框。
- 切换供应商时自动切换对应默认 Base URL 和模型列表。
- API Key 默认只保存在当前浏览器会话；后端只在调用期间使用。
- 后端可通过环境变量提供默认模型配置，但 Key 不得写入数据库、日志、API 响应、报告或导出物。
- 真实模型优先；未配置或调用失败时不得自动伪装为真实结果。
- 用户可以主动选择 Mock AI 运行；页面、持久化记录、报告和审计包均显示 Mock 标记。
- 真实调用失败后支持有限重试、再次尝试或主动切换 Mock。

## 5. 多文件资产与需求资料包

- 用户可以一次选择多份当前任务使用的需求资料，包括 SRS、实现规格说明、接口文档和其他支持格式。
- 系统自动计算文件名、类型、大小和 SHA-256，并建立资产来源记录草稿。
- 用户确认来源、使用权限和模型使用权限后，文件进入可选资料列表。
- 用户在“当前任务使用的文件”列表中勾选已登记资产，不再单独执行“添加新文件”或重复选择同名本地文件。
- 当前任务不要求用户命名；如系统需要显示多次分析任务，使用项目名称后自动追加“1、2、3……”等序号。
- “当前任务”是面向用户的本次分析输入集合；内部仍可将其保存为需求资料包，但“需求资料包”不作为主要用户界面术语。
- 需求版本是发布后的不可覆盖快照，不等同于当前任务，也不等同于本地文件夹。
- 用例模板也使用同一资产登记流程，但资产类型为“用例模板”。

## 6. 需求分析

- 解析器只负责读取文档结构、表格、段落、图片和来源位置；不能把每个文本片段直接当作最终需求。
- 真实模型负责在多文件上下文中识别需求、模块、测试项、验收条件、歧义、遗漏、冲突和建议测试点。
- 输出必须经过结构校验，并为每条结果保留需求来源引用。
- 用户主界面显示按模块分组的需求表，而不是逐条操作原子需求卡片。
- 需求表默认全部选中，每页最多 20 条，支持搜索、筛选、批量全选/取消和单条取消。
- 每条结果至少显示名称、需求类型、来源文件、原文位置、分析说明和问题标记。
- 原子需求和稳定需求 ID保留在详情及追踪关系中，但不作为普通用户的主要操作对象。
- 需求分析必须先展示并确认，未确认的内容不得作为正式用例依据。

## 7. 需求冲突表

- 当多份资料对同一能力的描述不一致时，系统建立独立的“需求冲突表”。
- 冲突表至少展示冲突主题、双方原文、来源文件和位置、影响模块、影响测试项、状态、处理人和处理说明。
- 冲突处理选项包括：以 SRS 为准、以实现规格为准、两者保留、待外部确认。
- 未解决冲突不进入已确认需求，也不得生成对应模块的正式用例。
- 默认只阻止受影响模块；无关模块可以继续生成。
- 支持“整批严格模式”，在该模式下任一未解决冲突都阻止整批生成。
- 冲突解决后可以只重新分析和生成受影响模块。

## 8. 用例生成与编辑

- 用例必须基于已确认需求和已确认测试范围生成，并显示真实模型或 Mock 标记。
- 先展示平台内的用例表预览，再允许导出。
- 用例默认全部纳入，支持按模块、测试项、优先级和状态筛选，并支持分页和批量操作。
- 用户可以编辑标题、优先级、预置条件、输入、操作步骤、预期结果、测试类型、模块、测试项、测试前备注信息和软件版本。
- 操作步骤与预期结果分别写入单个单元格，按编号连续换行，不插入空行。
- 用户编辑后标记为人工修改；原始模型结果可查看并恢复。
- “删除”默认表示移除出本次用例集，可恢复，不删除原始候选、追踪关系或审计记录。
- 支持查看已移除用例、恢复用例和批量移除。

## 9. 默认 Excel 模板与导出

默认模板来源为用户提供的“软件测试-测试用例-通用-工作中总结-模板表头.xlsx”，删除“父记录”列后保留以下 16 列及顺序：

`用例编号、测试用例标题、优先级、预置条件、输入、操作步骤、预期结果、测试类型、模块、测试项、测试结果、测试记录、测试前备注信息、计划执行时间、附件、软件版本`

- 生成阶段填写设计字段；测试结果、测试记录、测试前备注信息、计划执行时间和附件默认留空。
- 内置该模板作为默认模板；项目可以上传并确认自己的模板。
- 导出复制模板结构和格式，不修改原始模板。
- 默认导出 XLSX，并可提供 CSV 备用导出。
- 模板映射失败不得阻止平台标准用例预览；必须显示缺失字段或有损映射诊断。

## 10. 验收标准

- 新用户不看代码即可创建项目，并看到红色星号必填项和软件版本字段。
- 用户一次选择 SRS 与实现规格说明后，可以组成当前任务，无需重复选择同名文件或填写资料包名称。
- 使用真实模型时，页面能展示结构化需求分析摘要、需求表和来源位置；使用 Mock 时有醒目标识。
- 多文件冲突出现在独立冲突表中；未处理冲突不会生成受影响模块的正式用例。
- 用户能够默认全选需求、搜索并取消条目，再生成可读的用例表。
- 用户能够编辑用例、移除用例、恢复用例，并导出 16 列模板文件；“父记录”不存在。
- 导出的软件版本来自创建项目时填写的值，步骤和预期结果没有空行。
- API Key 不出现在持久化、日志、报告、审计包和下载文件中。
- 无 API Key 时系统明确提示真实分析不可用；Mock 需要用户主动选择。

## 11. 非目标

- 不实现旧项目代码迁移、旧 Prompt 复用、旧业务资料导入。
- 不在 rc.2 重做完整执行平台、设备控制、浏览器控制或缺陷管理系统。
- 不要求一次完成所有 V1 治理和变更影响能力；它们只能在不阻塞主流程的前提下保留。
