# 04 — 多文件结构化需求分析

**What to build:** 用真实模型在多文件上下文中生成结构化需求、测试项、来源引用和需求评审结果，并保留确定性校验与 Mock 路径。

**Blocked by:** 02 — 真实模型配置与安全隔离；03 — 多文件输入与已登记资产复用。

**Status:** resolved

- 需求分析不再把每个解析片段直接作为最终需求。
- 输出需求、模块、测试项、验收条件、歧义、遗漏和冲突。
- 每条结果必须有有效需求来源引用。
- 空输出、缺引用、Schema 错误和模型失败均有明确结果。

## Answer

- 新增 `requirement-analysis.v1` 结构化输出契约，覆盖需求、模块、测试项、验收条件和评审发现。
- 需求来源引用在模型输出进入内部分析前进行确定性校验，结果保留原始文件和定位信息。
- Mock 与 OpenAI-compatible 真实模型统一通过模型服务边界接入，真实模型使用当前会话配置且 API Key 不入库。
- 需求评审页面增加按模块归并的需求表，并保留既有人工确认流程。
