## 建议执行方式

先完成 01–04，尽快获得一次真实模型从多文件到结构化需求的纵向样例；再完成 05–08 的用户操作和交付能力；最后用真实模型与 Mock 各跑一遍验收。任何阶段都不应通过复制旧项目代码或业务资料来填补能力缺口。

## rc.2 完成门槛

- 至少一组包含 SRS 和实现规格说明的多文件输入可完成分析。
- 至少一组有冲突的输入能在独立冲突表中被阻断和解决。
- 至少一组需求能生成、编辑、移除、恢复并导出 16 列用例表。
- 有真实模型路径和明确的 Mock 离线路径，两者在页面和审计中可区分。
- API Key、Prompt 全文和不应导出的内部追踪信息不泄露到交付文件。
