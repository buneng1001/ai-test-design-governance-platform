# 10 — 完成三角色 AI 独立评审与用例确认

**What to build:** 对同一候选用例版本分别运行产品经理评审员、测试经理评审员和项目经理评审员，
再由测试工程师逐条处置 AI 评审建议，形成不可覆盖的用例修订版本并完成用例确认。

**Blocked by:** 09 — 生成可追踪的候选测试用例。

**Status:** resolved

- [x] 三个角色分别创建独立 AI 运行，并只接收完成本角色任务所需的最小上下文。
- [x] 任一角色运行时不能读取另外两个角色的建议或输出。
- [x] 每条 AI 评审建议保留角色来源、建议类型、理由、引用和限制。
- [x] 三个角色运行完成后可归并相似建议，但归并结果保留全部角色来源和原建议。
- [x] 测试工程师可逐条采纳、拒绝或修改建议，并形成 AI 处置记录。
- [x] 采纳或修改建议创建新的不可覆盖用例修订版本，不覆盖候选版本。
- [x] 用例确认关口分配稳定用例 ID，并记录用例纳入决定和确认人。
- [x] 未完成三角色评审或未处置必要建议时，不能完成用例确认。
- [x] API 与前端测试覆盖角色隔离、归并来源、逐条处置、修订差异和确认关口。
