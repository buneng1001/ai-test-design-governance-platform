# 14 — 导入多来源结果并治理复测与冲突

**What to build:** 测试工程师可向同一执行批次逐次导入多份人工结果输入和自动化结果输入，
保留每次执行事实，处理匹配、复测、执行异常、阻塞和结果冲突，并人工确认批次结论。

**Blocked by:** 13 — 创建执行批次与人工执行文件。

**Status:** resolved

- [x] 同一执行批次可接收多份人工结果输入、测试执行与诊断平台结果和其他通用自动化结果。
- [x] 结果优先按稳定用例 ID 和修订版本关联，其次使用已登记外部用例编号，最后进入人工匹配。
- [x] 低置信度、多个候选或版本不一致的结果不会自动归属，可由测试工程师明确匹配或拒绝。
- [x] 重复导入相同来源记录具有幂等结果，不创建重复用例执行记录。
- [x] 状态明确区分通过、执行失败、阻塞、未执行和执行异常，并按定义参与统计。
- [x] 再次执行创建新的用例执行记录和显式复测关系，不覆盖前次事实。
- [x] 同一用例同时展示初始结果、最新结果、完整执行历史和人工确认的批次结论。
- [x] 可比较条件下的人工与自动化差异形成结果冲突，AI 和导入时间均不能自动裁决。
- [x] 测试工程师可处理冲突并记录决定、理由和确认人。
- [x] API 与契约测试覆盖三份增量结果、全部状态、失败后复测通过、重复导入、模糊匹配和一次结果冲突。
- [x] 前端测试覆盖导入结果、处理冲突并确认批次结论的关键闭环。
