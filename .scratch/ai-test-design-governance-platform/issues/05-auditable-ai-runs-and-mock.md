# 05 — 建立可审计 AI 运行与确定性 Mock

**What to build:** 建立所有 AI 辅助能力共用的受控调用闭环，使一次模型调用成为不可覆盖的 AI 运行，
先经过结构校验再产生候选输出，并可通过确定性 Mock 在离线和 CI 环境复现正常及失败场景。

**Blocked by:** 02 — 建立资产来源记录与洁净重写护栏；03 — 导入文本与结构化需求资料并形成需求版本。

**Status:** resolved

- [x] 模型服务通过独立边界接入，业务流程不依赖特定模型提供方的数据结构。
- [x] 每次 AI 运行记录任务类型、模型参数、Prompt 版本、输入资产版本、输出、校验结果、耗时、状态和 Mock 标记。
- [x] 每类 AI 输出先通过版本化结构校验；校验失败保留审计事实但不创建测试设计资产。
- [x] 超时、限流和临时服务错误允许有限重试，每次尝试保留；鉴权、参数、安全和 Schema 错误不自动重试。
- [x] Mock 覆盖正常、空结果、来源缺失、Schema 错误和服务失败，并对相同输入产生确定性结果。
- [x] 模型不可用时，已确认资产、确定性统计、文件操作和已有报告仍可使用。
- [x] API、页面、持久化和导出中可明确区分 Mock AI 运行与真实模型运行。
- [x] 密钥只从后端环境读取，不出现在 API 响应、数据库、日志、报告或导出文件中。
- [x] API 测试验证结构校验、重试边界、审计不可覆盖、最小上下文和来源不明资产过滤。
