# 15 — 建立质量问题、缺陷模式和五类覆盖指标

**What to build:** 将已确认测试设计与执行批次结果汇总为可展开验证的覆盖指标，并以轻量质量问题引用和缺陷模式
支持治理判断，而不建设完整缺陷管理系统或让 AI 声称技术根因。

**Blocked by:** 07 — 完成测试维度、范围、风险和自动化候选设计；14 — 导入多来源结果并治理复测与冲突。

**Status:** resolved

- [x] 质量问题引用可记录现象、证据引用、严重程度、问题模式、外部缺陷编号、状态、发布影响、修复版本和复测。
- [x] 质量问题引用关联对应执行记录，但不承担分配、SLA、讨论、通知或完整缺陷工作流。
- [x] AI 可从多个质量问题引用提出缺陷模式候选，人工确认后才能成为治理资产。
- [x] 缺陷模式明确表示重复现象或触发特征，不作为已经证明的技术根因。
- [x] 需求覆盖率、风险覆盖率、测试维度覆盖、执行覆盖率和自动化覆盖率按正式定义确定性计算。
- [x] 每项指标均可展开查看分子、分母、已覆盖项和未覆盖明细，高风险缺口单独可见。
- [x] 只有已确认追踪关系建立覆盖事实，语义相似度和 AI 建议不能直接提高覆盖率。
- [x] 相同已确认输入产生相同指标，状态或关系变化后指标与明细同步更新。
- [x] API 测试以可检查夹具验证五类指标、边界分母、冲突结果和无效追踪关系。
- [x] 前端关键流程验证从治理指标进入缺口明细，并查看关联质量问题和执行证据。
