# 07 — 完成测试维度、范围、风险和自动化候选设计

**What to build:** 基于已确认原子需求形成项目测试维度、测试范围项、可解释风险和自动化候选，
由测试工程师调整并通过设计确认关口，使后续用例生成只使用已确认的设计资产。

**Blocked by:** 06 — 完成原子需求、需求评审与需求确认。

**Status:** resolved

- [x] 项目可维护分层项目测试维度，并支持新增、改名、移动、合并和停用。
- [x] 已被资产引用的维度不能直接删除，维度变更保留影响和历史记录。
- [x] AI 可提出维度建议和带原子需求追踪关系的测试范围项。
- [x] 每个测试范围项具有一个主要测试维度和可选次要测试维度，统计时不重复计算范围项。
- [x] AI 对风险因子提出风险建议分、理由和需求来源引用，系统用公开规则计算最终风险分和风险等级。
- [x] 人工调整风险因子必须记录理由，相同确认输入产生相同风险结果。
- [x] 测试优先级按风险、业务关键性、需求变更和历史结果等确定性输入形成。
- [x] 自动化建议与风险分开，覆盖价值、可行性、稳定性、成本和人工观察要求。
- [x] 测试工程师可确认四种自动化决定，首版不生成完整自动化脚本。
- [x] 设计确认前不能生成正式候选测试用例，确认后相关决定与确认人可审计。
- [x] API 和关键页面测试覆盖维度维护、风险调整、自动化决定和设计确认关口。
