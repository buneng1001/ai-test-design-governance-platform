# 03 — 导入文本与结构化需求资料并形成需求版本

**What to build:** 测试工程师可把多份 Markdown、TXT、JSON、YAML 和 OpenAPI 需求资料组成需求资料包，
发布为不可覆盖的需求版本，并能查看每份资料的解析结果、来源位置和诊断信息。

**Blocked by:** 01 — 建立本地应用骨架与测试设计项目闭环；02 — 建立资产来源记录与洁净重写护栏。

**Status:** completed

- [x] 同一测试设计项目可一次导入一份或多份受支持需求资料，并在发布前查看资料包清单。
- [x] Markdown、TXT、JSON、YAML 和 OpenAPI 的有效内容可被提取为统一、可引用的解析结果。
- [x] 每个来源片段保留稳定的需求来源引用，能够回到原文件及其中的原始位置。
- [x] 不支持、不可读、过大、格式错误或部分解析的文件返回明确诊断，不会被静默视为完整资料。
- [x] 发布资料包会创建不可覆盖的需求版本；后续导入创建新版本而不修改旧版本。
- [x] 原始资产、内容哈希、解析结果和诊断均与对应需求版本关联并可查询。
- [x] API 测试覆盖所有格式、批量导入、部分失败、版本不可变性和来源引用有效性。
- [x] 页面关键流程覆盖选择多文件、查看诊断并发布需求版本。
