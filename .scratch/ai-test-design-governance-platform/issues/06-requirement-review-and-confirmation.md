# 06 — 完成原子需求、需求评审与需求确认

**What to build:** 测试工程师可对一个需求版本运行原子需求提取和需求评审，复核来源、视觉推断和评审发现，
最终通过需求确认关口建立后续测试设计可依赖的正式需求事实。

**Blocked by:** 04 — 扩展 DOCX、PDF 与截图需求资料；05 — 建立可审计 AI 运行与确定性 Mock。

**Status:** ready-for-agent

- [ ] AI 提出带需求来源引用的原子需求候选，不改写或覆盖原始需求资料。
- [ ] 测试工程师可拆分、合并、修改、接受或拒绝原子需求候选。
- [ ] 首次确认的原子需求获得稳定需求 ID，并保留与需求版本及来源的关系。
- [ ] AI 可提出规格定义的需求评审发现类型，并记录理由、来源或推断标记。
- [ ] 测试工程师可按正式枚举处置评审发现，且每次状态变化可审计。
- [ ] 视觉推断在人工确认前不能作为正式需求事实。
- [ ] 需求确认关口未通过时，正式范围、风险和用例生成 API 拒绝继续推进。
- [ ] API 测试覆盖候选编辑、稳定身份、发现状态、无效引用、确认关口和不可变历史。
- [ ] 前端测试覆盖处理一个原子需求、一个评审发现和一个视觉推断后完成需求确认。
