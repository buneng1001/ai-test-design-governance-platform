# 01 — 项目专用 Skill 与结构化契约基线

**What to build:** 将需求分析与用例生成方法派生为随项目版本化发布的两个专用 Skill，使 Step 00～08、测试点到详细用例的交接、字段约束和追溯规则成为后续页面与工作流共同遵循的可验证契约。该任务完成后，可以用合成需求在不依赖前端的情况下验证阶段输入、输出和编号映射。

**Blocked by:** None — can start immediately.

**Status:** ready-for-agent

- [ ] 仓库内存在重新命名后的 `ai-test-design-requirement-analysis` 和 `ai-test-design-case-generation` 两个专用 Skill，运行时不依赖工作区外原始 Skill。
- [ ] 需求分析 Skill 明确定义 Step 00～08 的输入、输出、依赖和失败状态，并明确只到测试点与覆盖自检，不越界生成详细用例。
- [ ] 用例生成 Skill 接收 Step 07 的已确认测试点以及关联需求、规则和范围，输出可编辑的候选用例结构。
- [ ] 两个 Skill 统一支持 P0～P3，并保留目标、逐步预期、整体预期、证据要求、设计依据和软件版本等正式字段。
- [ ] Skill 阶段编号与平台稳定 ID 允许格式不同，但有确定、可校验的映射，能够从用例反查测试点和需求来源。
- [ ] 正常、信息不足和模型失败三类合成场景通过结构验证，且不包含固定业务示例或伪造成功结果。
- [ ] 明确版本升级和兼容策略，使 Prompt 或模板变化不会静默改变已有阶段产物的解释方式。

**Out of scope:** 不实现通用 Skill 市场、动态安装、浏览器直接解释 `SKILL.md`，也不在本任务内调优全部真实模型效果。
