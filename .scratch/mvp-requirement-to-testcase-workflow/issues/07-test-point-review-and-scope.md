# 07 — Step 07～08 测试点审核与范围选择

**What to build:** 系统将已确认需求和已处置建议组织为需求模块、测试项和测试点，在“审核”页提供追溯、覆盖自检和范围选择。用户确认的测试项或测试点集合成为详细用例生成的唯一输入范围。

**Blocked by:** 06 — Step 03～06 新增建议与处置闭环.

**Status:** ready-for-agent

- [ ] 每个测试项至少关联一个已确认需求 ID，每个测试点关联有效测试项，并可回溯需求、规则和来源。
- [ ] 测试点根据适用性覆盖正常、异常、边界、风险和权限等方向，只表达“测什么”，不提前混入详细步骤和预期。
- [ ] 审核页清楚展示需求模块、测试项、测试点和预计用例之间的层级与数量关系，并默认折叠专家设计依据。
- [ ] Step 08 以确定性规则识别孤立需求、孤立测试点、关系缺失和覆盖盲区，覆盖率可从明确关系复算。
- [ ] 用户能够按测试项或测试点选择生成范围；未选择范围不会进入用例生成请求或结果。
- [ ] 阻塞建议未处理时只限制受影响范围，审核确认后保存稳定的交接版本和选择结果。
- [ ] Skill 测试点编号与平台 ID 保持稳定映射，并支持按需导出 Step 00～08 兼容 Markdown 分析包。
- [ ] 契约、API 和组件测试覆盖层级追溯、适用方向、覆盖自检、范围选择和未选择项隔离。

**Out of scope:** 不在本任务生成包含步骤、数据和具体预期的详细测试用例。
