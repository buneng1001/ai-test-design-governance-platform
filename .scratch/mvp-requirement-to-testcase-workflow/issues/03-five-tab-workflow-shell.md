# 03 — 五页签主流程框架与状态恢复

**What to build:** 将默认工作台收敛为“上传文档、结构预览、新增建议、审核、测试用例”五个顺序页签，并提供统一的左侧模型与步骤区。用户刷新或重新进入项目时，能够从后端恢复当前步骤、阻塞原因和下一步操作，而不需要理解后台治理对象。

**Blocked by:** 01 — 项目专用 Skill 与结构化契约基线.

**Status:** ready-for-agent

- [ ] 默认入口只展示五页签主流程和必要的项目上下文，资产来源、AI 审计、执行批次、治理指标、变更影响与报告不再占据首屏。
- [ ] 页签根据正式工作流状态依次解锁，并清楚显示未解锁原因、当前步骤和下一步动作。
- [ ] 左侧区域容纳模型配置、连接状态、步骤导航和运行摘要，并在窄屏下保持可访问。
- [ ] 后端提供统一的工作流查询视图，聚合当前步骤、阻塞项、进度、可执行动作和关键资产标识；阶段命令仍保持明确边界。
- [ ] 刷新页面或重新打开项目后，页签状态、用户选择和可继续动作能够从持久化状态恢复。
- [ ] 修改上游已确认内容时，受影响的下游草稿被明确标记为需要重新确认，不会静默继续沿用。
- [ ] 组件和 API 测试覆盖初始状态、逐步解锁、阻塞状态、刷新恢复和上游变更失效。

**Out of scope:** 不在本任务实现各页签的完整业务内容，也不删除仍被后台 API 和历史数据使用的领域对象。
