# 09 — AI 运行稳定性与人工控制

**What to build:** 需求分析和用例生成共享一致的运行控制体验：按范围分批执行，显示真实阶段、完成数量和预计时间，允许停止并从明确检查点恢复；系统只对暂时性错误有限重试，对结构错误进行受限修复，并在明确标记下提供模板回退。

**Blocked by:** 05 — Step 01～02 结构预览与单一需求确认; 08 — 详细测试用例生成与管理.

**Status:** ready-for-agent

- [ ] 需求分析和用例生成按章节、需求、测试项或测试点拆成有上限的批次，每批只携带必要上下文。
- [ ] 页面显示当前 Skill 阶段、当前批次、完成数量、总数量、运行来源和基于实际吞吐的可理解预计时间。
- [ ] 用户停止后不再启动新批次，已完成且校验通过的阶段产物保留；继续运行从明确检查点开始且不会重复创建资产。
- [ ] 超时、限流、连接重置和供应商 5xx 按次数与退避上限自动重试；鉴权、参数、内容安全和稳定结构错误不盲目重试。
- [ ] 无效 JSON 或 Schema 输出先经过一次确定性本地修复，必要时最多执行一次不得新增业务内容的结构修复请求。
- [ ] 每次尝试记录错误分类、脱敏诊断、输入与 Prompt 版本、恢复点和最终状态，不记录 API Key 或不必要的完整敏感正文。
- [ ] 真实模型无法使用时，用户可以明确选择模板回退；回退使用相同输入输出契约，并在页面、持久化和预览中醒目标记来源。
- [ ] Mock、真实模型和模板回退可明确区分，任何备用模型或供应商降级都需用户明确同意。
- [ ] 确定性替身测试覆盖超时后成功、限流耗尽、鉴权失败、Schema 错误、引用缺失、截断、停止、恢复和回退。

**Out of scope:** 不以无限重试、静默切换模型或伪造完成状态换取表面成功率。
