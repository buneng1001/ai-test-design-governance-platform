# 08 — 详细测试用例生成与管理

**What to build:** 用户在审核页确认范围后，由项目专用用例 Skill 和真实模型输出形成可编辑、可追溯的候选用例，而不是用通用成功响应触发固定模板文案。用户可以在“测试用例”页评审、编辑、移除和恢复候选，并始终追溯到测试点、测试项和需求。

**Blocked by:** 01 — 项目专用 Skill 与结构化契约基线; 02 — AI 模型安全接入与连接验证; 07 — Step 07～08 测试点审核与范围选择.

**Status:** ready-for-agent

- [ ] 生成输入只包含用户选中的测试项或测试点及其必要需求、验收条件、规则、来源摘要和软件版本。
- [ ] 模型输出实际决定用例标题、目标、前置条件、数据或输入、步骤和预期，不再由固定模板替代真实生成内容。
- [ ] 每条候选用例具有 P0～P3 合法优先级、连续步骤、逐步预期、整体预期、证据要求、设计依据和软件版本。
- [ ] 每条用例关联有效测试点、测试项和稳定需求 ID，且可以定位到 Step 07 编号和来源材料。
- [ ] 不同边界值或等价类可形成独立、稳定编号的用例；重复候选能够通过确定性候选键识别。
- [ ] 不确定的阈值、文案或行为明确标记待确认，不会被保存为材料事实。
- [ ] 用户能够搜索、筛选、批量选择、编辑、移除、查看已移除项和恢复用例，人工修改不覆盖原始候选与审计信息。
- [ ] 结构、字段、引用和跨对象关系校验成功后候选才可进入可编辑草稿；生成失败时不伪造正式资产。
- [ ] API、领域契约和组件测试覆盖真实模型结构进入候选、完整字段保存、编辑与恢复、追溯和范围隔离。

**Out of scope:** 不在本任务完成跨阶段统一的重试、停止恢复、模板回退和最终 XLSX/CSV 导出。
