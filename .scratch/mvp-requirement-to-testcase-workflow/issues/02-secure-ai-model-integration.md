# 02 — AI 模型安全接入与连接验证

**What to build:** 用户能够在主流程左侧选择服务商、Endpoint 和模型，按需发现模型并执行连接测试；系统按统一规则解析本地或临时凭据，给出可操作的结构化错误，同时不再把 API Key 明文保存到业务数据库、日志或响应中。

**Blocked by:** None — can start immediately.

**Status:** ready-for-agent

- [ ] DeepSeek、硅基流动、Kimi、GLM 和自定义 OpenAI 兼容服务的配置与凭据相互隔离，不跨服务商复用 Key。
- [ ] 项目根目录的 `.env.local` 能由本地后端按约定加载，并保持 Git 忽略；临时 Key、明确记住的本地 Key、项目默认环境变量按既定优先级解析。
- [ ] 用户未选择“记住”时，Key 不写入数据库或磁盘；选择记住时只写入被忽略的本地凭据配置，页面和 API 不回显原值。
- [ ] 现有数据库明文 Key 不再被使用，并通过兼容迁移清除或转换为不含原值的状态记录。
- [ ] 用户可以主动发现模型；预设、已发现、已验证、失败、失效和手动输入模型具有可区分状态，普通页面刷新不会重复产生发现调用。
- [ ] 连接测试成功后保存不敏感的验证记录；Key 或 Endpoint 变化会使原验证记录失效。
- [ ] 连接和调用失败返回统一的错误阶段、服务商、模型、错误类型、可重试性、用户消息、建议动作和脱敏详情。
- [ ] 使用确定性替身验证服务商隔离、Key 优先级、模型发现、连接成功和常见错误，自动化测试不消耗真实额度。

**Out of scope:** 不自动切换供应商、备用模型或 Mock，也不把真实供应商调用作为 CI 前置条件。
