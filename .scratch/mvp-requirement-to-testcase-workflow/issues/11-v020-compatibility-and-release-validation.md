# 11 — 历史兼容、后台治理隔离与 v0.2.0 验收

**What to build:** 完成 v0.2.0 的兼容升级和发布验收：旧需求、评审、测试设计与用例仍可读取，后台治理能力继续可用但不阻塞五页签；普通用户通过一条浏览器级主流程即可从上传走到导出，并有自动化与受控真实模型证据证明系统可交付。

**Blocked by:** 09 — AI 运行稳定性与人工控制; 10 — 质量检查与结果导出.

**Status:** ready-for-agent

- [ ] 数据变化采用兼容的追加迁移，升级前需求版本、评审记录、测试设计、候选用例、稳定需求 ID 和已有追溯关系仍可读取。
- [ ] 无法映射到新主流程的历史字段保留在高级详情，迁移不会破坏性删除仍有价值的后台数据。
- [ ] 资产来源、AI 运行审计、执行批次、治理指标、变更影响和详细报告通过高级入口或细粒度 API 保持可用，但未配置或待处理状态不阻塞主流程。
- [ ] 一条浏览器级验收测试使用小型合成需求包完成上传、解析、确认、建议处置、范围选择、用例生成和导出，全程无需进入高级后台。
- [ ] 后端契约、前端组件、Skill 映射、模型接入、导出和历史兼容测试全部通过，既有后台治理测试无回归。
- [ ] 使用受控小型需求包至少完成一次真实模型验收，确认结构化模型输出实际形成需求和用例；自动化测试与 CI 仍不依赖真实 Key。
- [ ] 验证不存在会导致未选择需求进入下游、稳定 ID 改变、AI 失败伪装成功、停止失效或导出不可用的高优先级已知问题。
- [ ] 仅删除已由新入口替代且确认无后台用途的旧首屏组合死代码，不删除仍有兼容或审计价值的能力。
- [ ] v0.2.0 的运行、配置、凭据安全、主流程和已知限制文档与实际行为一致。

**Out of scope:** 不在本版本恢复执行批次为主流程步骤，不实现账户、多角色审批、多人实时协作、通用插件市场或 Skill 动态调度。
