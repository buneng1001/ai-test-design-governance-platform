# 06 — Step 03～06 新增建议与处置闭环

**What to build:** 对已确认且已选择的需求执行正常、异常、边界和隐性风险分析，在“新增建议”页形成可追溯建议。用户能够采纳、拒绝、修改或标记待外部确认；采纳为新需求事实的内容必须重新经过确认，不能由 AI 静默写入基线。

**Blocked by:** 05 — Step 01～02 结构预览与单一需求确认.

**Status:** ready-for-agent

- [ ] Step 03～06 只使用已确认且处于分析范围内的需求、规则和来源摘要，不把未选择需求重新带入 Prompt 或结果。
- [ ] 建议覆盖正常场景、异常场景、边界条件和隐性风险，并标明材料明示、人工确认、分析推导或待确认来源类型。
- [ ] 每条建议显示关联需求、来源依据、影响范围和问题类型，能够定位回需求行和原始材料。
- [ ] 用户可以采纳、拒绝、修改或标记待外部确认，所有处置状态在刷新后保持一致。
- [ ] 被采纳为新需求的建议返回需求确认环节，只有再次确认后才获得稳定需求 ID 并进入下游范围。
- [ ] 冲突和待确认问题只阻塞受影响的需求或模块；无关且完整的范围仍可继续处理。
- [ ] AI 结构或引用校验失败只留下可理解诊断，不会把推导内容写成已确认事实。
- [ ] API 和组件测试覆盖四类处置、建议回流、局部阻塞、未选择项隔离和刷新恢复。

**Out of scope:** 不在本任务确认测试项、生成测试点或产生详细用例步骤。
