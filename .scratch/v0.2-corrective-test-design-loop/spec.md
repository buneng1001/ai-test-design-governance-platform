# v0.2.0 纠偏需求规格：需求分析到测试用例

Status: ready-for-human

## Problem Statement

测试工程师使用本平台，是为了读懂需求、识别测试点，并把已选择的测试范围生成客户可使用的测试用例。当前 v0.2.0 将模型配置、批次和运行状态置于主路径，却没有让用户看见、选择和使用 AI 对需求作出的分析结果。

产品必须把“文档解析结果”和“AI 需求分析结果”分开：前者不调用 AI，后者必须明确说明是否已调用 AI、结果是什么、能否下载，以及哪些内容会成为测试用例范围。

## Solution

项目管理是独立于项目工作台的第一层入口，负责创建、打开、搜索、归档和恢复测试设计项目。测试工程师先选择一个项目，再进入该项目的五个工作页签：

`上传文档 → 需求分析 → 新增建议 → 审核 → 测试用例`

上传文档只负责本地解析和显示解析结果。需求分析、新增建议、审核和测试用例均是独立的 AI 工作页；每页均由用户选择“真实模型（直接调用）”“真实模型（Skill 工作流）”或“本地模式（不调用 AI）”，并显示本页的未执行、执行中、已完成或失败状态、结果来源和下载入口。

需求分析使用 `ai-test-design-requirement-analysis` 的 Step 00～08 语义，产出功能点、测试项、测试点、来源依据、信息缺口和覆盖自检。测试用例使用 `ai-test-design-case-generation` 的契约，只接收用户在“需求分析”页勾选的测试范围。浏览器不直接执行 `SKILL.md`；后端须以版本化工作流落实其输入、输出和校验规则。

唯一的端到端业务缝是：**在项目中上传并解析资料，执行需求分析，在需求分析表中勾选测试范围，生成、预览、确认并下载测试用例。** 新增建议和审核为可选的 AI 增强步骤，不能阻塞这条主线。

## User Stories

1. 作为测试工程师，我希望上传文档后立刻看到解析出的文件、章节、表格、正文片段和解析状态，以便确认系统读到了什么。
2. 作为测试工程师，我希望上传页明确标注“本页面不调用 AI”，以便区分文档解析与真实 AI 调用。
3. 作为测试工程师，我希望在上传前或上传后填写补充说明，以便说明关注功能、已知修改、术语或需要忽略的内容。
4. 作为测试工程师，我希望在需求分析页选择真实 AI 或本地模式，并点击“开始需求分析”，以便明确何时开始分析。
5. 作为测试工程师，我希望需求分析页显示分析是否已执行、执行方式、模型/本地来源、时间和失败原因，以便知道页面是否已有结果。
6. 作为测试工程师，我希望在一张可按功能筛选的大表中查看 AI 分析出的功能点、测试项和测试点，以便判断分析是否正确。
7. 作为测试工程师，我希望直接勾选或取消勾选分析表中的内容，以便明确后续测试用例的测试范围。
8. 作为测试工程师，我希望未勾选或被取消勾选的需求分析内容绝不进入用例生成，以便排除错误或无关内容。
9. 作为测试工程师，我希望使用“新增建议”页让 AI 主动发现遗漏测试点，以便 AI 而非人工承担补充覆盖面的工作。
10. 作为测试工程师，我希望逐条接纳或拒绝新增建议，并让接纳的建议回流到需求分析表，以便与原始分析结果一起选择范围。
11. 作为测试工程师，我希望可选地让产品经理、项目经理或测试经理 AI 身份审核当前需求点，以便观察风险、缺口和项目可行性。
12. 作为测试工程师，我希望可以跳过审核直接进入测试用例，以便审核不成为日常生成用例的阻塞步骤。
13. 作为测试工程师，我希望审核建议由我自行决定是否接纳，以便 AI 身份不是审批人。
14. 作为测试工程师，我希望测试用例页依次包含用例模板选择、生成模式选择、生成操作、用例预览、编辑、选择纳入和下载，而不是分散到额外页面。
15. 作为测试工程师，我希望测试用例生成只能使用需求分析表中已勾选的测试范围，以便每条用例都有明确依据。
16. 作为测试工程师，我希望每个 AI 工作页都能下载本页结果，以便独立复核或交付：需求分析表、新增建议、审核报告和测试用例。
17. 作为测试工程师，我希望真实 AI 调用前看见模型、将发送的输入摘要和 Token 估算，以便决定是否消耗 Token。
18. 作为测试工程师，我希望本地模式结果醒目标注为本地模拟，且不伪装成真实 AI 结果。
19. 作为测试工程师，我希望在同一模型和同一输入下分别运行“直接调用”和“Skill 工作流”，并查看结构化结果差异，以便决定默认模式。
20. 作为测试工程师，我希望 AI 运行时看见当前阶段、已用时间、预计剩余时间、Token 估算/实际用量和费用估算/实际费用状态，以便理解成本与等待原因。
21. 作为测试工程师，我希望在测试用例页先选择使用默认测试用例模板或上传自己的模板，再选择生成模式，以便生成文件符合实际交付格式。
22. 作为测试工程师，我希望从项目管理进入不同测试设计项目，以便在不同产品或版本中分别保留资料、分析、用例和历史记录。
23. 作为测试工程师，我希望下载一个项目交付包，以便一次取得本项目五个页面产生的资料、分析、建议、审核、测试范围、用例和下载清单。
24. 作为测试工程师，我希望刷新页面或再次进入项目后恢复此前资料、需求版本、分析运行、已选测试范围、用例生成记录和导出记录，以便不会重复上传或重复消耗 Token。
25. 作为测试工程师，我希望针对已保存的需求分析结果筛选某个功能点或测试项，直接选择部分范围再次生成用例，以便不用重复上传和分析整个项目。
26. 作为测试工程师，我希望需求分析表和测试用例表支持搜索、筛选、分页、每页条数和跨页保留选择，以便在数百条结果中仍可复核和生成。

## Implementation Decisions

### 项目管理、项目历史与项目交付包

- 项目管理不得删除。它显示项目名称、测试对象、软件版本、最近更新时间、当前需求版本、最近一次分析/用例生成状态和最近导出时间；支持创建项目、打开项目、搜索项目和归档项目。
- 一个测试设计项目持久化拥有需求资料包及其版本、文档解析结果、补充说明、需求分析运行、分析表勾选状态、新增建议及处置、可选审核运行及处置、测试用例模板、候选/确认用例、导出记录和 AI 运行记录。刷新、关闭浏览器或重新进入同一项目后，前端按项目 ID 重新读取这些资产，不能依赖浏览器内存恢复。
- 测试工程师可从已有需求版本和已有需求分析表中筛选未覆盖的功能点或测试项，形成新的用例生成范围；只要资料和分析仍适用，就不得要求重新上传或重新分析。
- 项目管理和项目工作台均提供`下载项目交付包`。交付包以 ZIP 导出，至少含项目清单、需求资料版本与解析结果、需求分析表及运行摘要、新增建议及处置、审核报告及处置、各次测试范围选择、测试用例模板映射、候选/确认用例文件和导出清单；不得包含 API Key 或明文敏感凭据。
- 历史运行必须可按时间、页面、真实/Skill/本地模式和结果状态检索。用户可以打开历史结果、下载对应产物，或将历史需求分析表重新作为范围选择依据；不能因页面刷新丢失。

### 模型接入：复用已有能力，不在工作页重画

- 复用现有模型配置页面及其前端 UI：供应商选择、全量已发现模型下拉、Endpoint、临时/本地凭据来源、记住凭据、模型发现、真实模型预检和已验证状态。不得在五个工作页重新设计第二套模型配置表单。
- 工作页只显示当前已生效的服务商、模型、凭据来源和连接状态，并选择“直接调用 / Skill 工作流 / 本地模式”这一运行方式；用户点击“打开模型配置”时进入或弹出既有模型配置 UI。
- 本地模式不要求模型配置；选择真实模型模式而连接未验证时，页面阻止调用并引导用户打开既有模型配置完成预检。

上传文档中的“上传并解析”是唯一入口按钮：上传、解析和解析结果展示属于同一个无 AI 功能。删除“需求点估算”这一额外按钮；“需求点估算”不能替代真实的需求分析，也不应制造第二个入口。

### 上传文档：解析结果与补充说明

- 补充说明是用户对本次资料的业务指令，例如关注范围、已知改动、术语、优先级或排除项。它在后续 AI 页面作为明确标注的人工补充输入，不得写成文档事实。
- 上传并解析后，在当前页直接显示解析结果；用户无需跳转即可确认文件内容是否可用。
- 解析失败必须指明文件和原因；解析成功不能暗示已做过 AI 需求分析。

### 需求分析：唯一的测试范围选择处

- “开始需求分析”是本页唯一的分析启动按钮。用户先选择真实模型（直接调用）、真实模型（Skill 工作流）或本地模式；真实模式点击后调用对应工作流，本地模式生成确定性本地模拟结果。
- 真实 AI 调用前的确认区域必须显示模型、输入资料摘要、补充说明、估算 Token 和“确认开始需求分析”；取消即零次模型调用。
- 结果以一张大表呈现，并支持按模块、功能点、测试项、来源、状态和是否勾选筛选。行可展开查看原文来源、AI 推导与信息缺口。
- 需求分析表默认每页 20 条，用户可选择 20、50 或 100 条；表头显示“共 N 条、当前筛选命中 M 条、本页 X–Y 条”。必须提供关键词、功能模块、功能点、测试项、来源、勾选状态和分析状态筛选，以及`清除筛选`。
- 勾选状态按分析结果 ID 持久化并跨页保留。`全选本页`只选择当前页，`全选当前筛选结果`必须显示受影响数量并要求确认；筛选或翻页不得清除已选测试范围。
- 用户的勾选就是正式测试范围，不另设“测试范围确认”页。页面固定显示已选数量和“这些内容将用于生成测试用例”。
- 被接纳的新增建议或审核建议回流至此表，默认未勾选，必须由用户明确纳入测试范围。
- 同一资料、补充说明、模型和范围可分别运行“直接调用”和“Skill 工作流”；两份结果独立保存并可并排比较，比较后由用户决定后续默认模式，首版不预设二者之一为默认。

### 新增建议：AI 负责补全，不要求人工猜测

- “AI 分析新增建议”以前一页的需求分析结果、补充说明和已选范围为输入，识别遗漏功能、测试项或测试点。它同样提供直接调用、Skill 工作流和本地模式。
- 人工职责是判断单条建议是否接纳、是否需编辑，不承担判断“测试点是否足够全面”的主要工作；该能力由 AI 建议和后续可选审核共同提供。
- 接纳建议后写入需求分析表，保留 AI 来源、建议 ID 和关联依据；拒绝建议保留处置记录但不进入测试范围。

### 审核：可选的三个 AI 身份

- 审核对象是当前需求分析表中的需求点和测试范围，不是要求测试工程师再次手工审核全部需求。
- 产品经理 AI 从业务价值和需求完整性提出建议；项目经理 AI 从风险、依赖和交付可行性提出建议；测试经理 AI 从可测试性和覆盖缺口提出建议。
- 用户可以只选一个身份，也可以完全跳过该页。审核结果不是前置审批，不影响直接生成测试用例。
- 用户对每条审核建议选择接纳或不接纳；接纳项回流需求分析表，用户仍在该表决定是否勾选为测试范围。
- 审核页同样提供三种运行方式。现有两个项目 Skill 已明确需求分析和用例生成的步骤；产品经理、项目经理、测试经理的角色审核提示模板必须作为独立的版本化资源补充，不能虚称为现有两个 Skill 中已存在的内容。

### 测试用例：配置、生成、预览和导出在同一页

- 页面上方不是名为“生成配置”的功能区，而是固定顺序的表单：先选择`使用默认测试用例模板`或`上传测试用例模板`，显示模板解析/字段映射预览；再显示已选测试范围；然后选择真实模型（直接调用）、真实模型（Skill 工作流）或本地模式，并填写补充生成要求。
- “生成测试用例”是唯一生成按钮。真实 AI 模式只发送当前已勾选的测试点及其必要来源；Skill 工作流模式按用例生成 Skill 的输入、测试方法和输出契约执行；本地模式不调用外部模型，并标记结果来源。
- 页面下方在生成完成后直接展示可编辑候选用例表及详情，支持勾选纳入、移除、恢复、质量提示、Excel 和 JSON 下载。
- 每条候选用例必须反查需求分析表中已勾选的测试点、测试项和需求来源；未勾选项生成零条用例。
- 测试用例表同样默认每页 20 条，并支持关键词、功能模块、测试项、测试点、优先级、纳入状态、生成方式和生成记录筛选。用户可以在“本次生成 / 历史生成记录”间切换，历史记录保留生成时间、模型/模式、范围、用例数量、状态和下载入口。

### Skill 工作流模式

- “真实模型（Skill 工作流）”不是旧的模板回退，也不是浏览器读取 `SKILL.md`；它是后端将当前页对应的 Skill 步骤、版本化提示模板、输入上下文和结构化校验组成一次真实模型运行。
- 需求分析 Skill 工作流执行 Step 00～08；新增建议调用其测试点补全与覆盖自检语义；测试用例 Skill 工作流只接收已选 Step 07 测试点。每次运行保存 Skill/提示版本、模型、输入范围和校验结果。
- 为了体验差异，直接调用和 Skill 工作流必须使用相同的资料范围、补充说明、模型和输出契约；页面显示两次运行的结果、耗时、Token 与费用数据，不能以不同输入掩盖模式差异。

### 模式、进度、Token、费用与运行状态

- 除上传文档页外，每个 AI 工作页都独立显示并选择三种模式；不要求用户在上传前配置模式。页面必须明确标出当前结果来自直接调用、Skill 工作流还是本地模式。
- 真实 AI 调用确认框显示提供方、模型、输入摘要、Skill/提示版本、预计输入 Token、最大输出 Token、费用估算和“确认开始”。浏览、筛选、勾选、编辑和下载均不能暗中调用 AI。
- 运行开始即创建可读取的运行记录，并向前端提供阶段事件：准备输入、调用模型、校验输出、保存结果、完成或失败。页面在请求等待期间持续显示已用时间；只有历史同类运行足够时才显示“预计剩余时间（估算）”，不得伪装成精确倒计时。
- 调用前 Token/费用为估算；调用后应优先保存服务商返回的输入、输出和总 Token，并依照该模型在调用时的已登记价格计算“实际费用”。服务商未返回用量或价格未知时，页面明确显示“实际用量/费用不可获得”，不得以估算冒充实际账单。
- 每页都显示“尚未执行 / 正在执行 / 已完成 / 失败”、结果来源、执行时间、实际/估算用量和失败后的下一步建议。
- 正常规模的需求资料在用户视角是一轮完整分析，不展示技术性“第 N 批”；超出模型能力时，产品必须在调用前要求用户按资料或章节缩小范围，不能按解析行自动切分后伪装成需求分析批次。

## Testing Decisions

- 前端原型先验证五个页签是否清楚展示输入、按钮、三种运行模式、执行状态、结果表、测试范围和下载按钮；原型未经人工确认，不实现后端。
- 上传并解析测试验证无论成功、失败或下载解析结果，均不发生模型调用。
- 项目恢复测试验证刷新页面、关闭后重新进入、切换项目和打开历史记录时，资料、分析表、测试范围、用例及导出记录均按项目 ID 恢复；结果未知的真实 AI 运行先查询状态，不能盲目重放调用。
- 项目交付包测试验证 ZIP 含五页签产物和清单、不含 API Key；空步骤在清单中明确标为未执行而不是静默缺失。
- 需求分析测试验证直接调用、Skill 工作流和本地模式可区分；同一输入的直接调用与 Skill 工作流结果可并排查看；只有已勾选分析表行进入测试用例生成输入。
- 大表测试验证 20/50/100 每页条数、关键词和各维度筛选、跨页选择、全选本页与全选筛选结果的数量提示；500 条结果不得一次性完整渲染。
- 新增建议与审核测试验证 AI 建议可接纳或拒绝、接纳后回流需求分析表，且审核可跳过。
- 审核模式测试验证三个角色可独立选择；角色审核提示模板带版本，且不能伪称来自现有需求分析或用例生成 Skill。
- 测试用例测试验证默认模板与上传模板均可选择并显示解析映射；候选预览、编辑、导出和追溯关系均在同一页完成。
- 运行状态测试验证准备、调用、校验、保存和终态事件可见；估算与实际 Token/费用严格区分，服务商未提供用量时显示不可获得。
- 持续集成使用确定性本地模式或模型服务替身，不调用真实提供方。

## Out of Scope

- 多人账号、真实审批流、消息通知、执行批次、缺陷管理、变更治理和精确人民币费用预测。
- 把产品经理、项目经理或测试经理 AI 视为拥有发布权限的真实审批人。
- 浏览器直接执行 Codex Skill，或保留含义不清的“模板回退”模式。
