# 智能采集设备合成需求包计划

## 1. 目的

从零创作一套可公开演示的智能采集设备需求资料，用于验证需求评审、范围分析、风险、用例生成、三角色评审、
任务导出、结果治理和需求变更闭环。它不是任何真实公司产品的脱敏版本。

## 2. 虚构产品边界

使用全新虚构名称和标识。产品由设备本体、Web 控制页面和公开演示 API 构成，可配置并采集视频、音频、IMU 和状态数据。
所有接口路径、字段、状态、错误码、阈值和示例数据从零设计。

平台演示覆盖完整产品测试，不把业务主题限定为视频、IMU 或同步专项。

## 3. 资料组成

### V1 需求包

- 产品需求说明：目标用户、核心流程和业务规则。
- 设备状态说明：初始化、待机、采集中、停止中、异常和恢复。
- 配置说明：采集参数、持久化、边界与非法输入。
- Web 页面说明：设备连接、任务配置、状态展示和文件管理。
- OpenAPI：设备状态、配置、采集控制和文件列表接口。
- 数据输出说明：通道、元数据、文件命名和基础完整性要求。
- 错误码与提示说明。
- 一组完全合成的页面截图。

### V2 需求包

在 V1 基础上设计 8–12 个明确变化：

- 新增需求。
- 修改验收阈值或状态规则。
- 删除不再提供的能力。
- 拆分或合并原有需求。
- 更改接口字段或错误码。
- 增加异常恢复或安全约束。
- 加入至少一个看似无关但实际影响回归范围的变化。

## 4. 功能模块

- 开关机、初始化和设备状态。
- 采集任务创建、开始、停止和重复执行。
- 参数配置、回读、持久化和恢复默认。
- 本地存储、容量预警、文件列表、下载和删除保护。
- Wi‑Fi、蓝牙和设备发现连接。
- Web 控制页面和状态一致性。
- 用户提示、错误码和操作反馈。
- 低电、过温、满盘、断网和异常退出恢复。
- 软件或固件升级、失败回滚和版本显示。
- 权限、敏感数据和导出保护。

## 5. 质量维度

- 功能与状态迁移。
- API 与数据一致性。
- UI 和人工体验。
- 性能、稳定性与压力。
- 异常恢复和数据保护。
- 兼容性与环境影响。
- 视频、音频、IMU、时间戳和多路同步专项。
- 端到端采集、停止、文件输出和解析链路。

## 6. 评审问题植入

V1 人为植入 10–15 个问题，类型至少包括：

- “快速”“稳定”“及时”等没有量化。
- 同一状态在两份资料中定义冲突。
- 缺少异常路径或恢复条件。
- 接口字段必填性与页面行为不一致。
- 错误码存在遗漏或重复含义。
- 边界值、时间起点或统计口径不明确。
- 页面截图暗示功能，但正式文字没有定义。
- 依赖模块尚未明确交付条件。
- 一条复合需求包含多个可独立验证的规则。
- 一个合理但不应被当成正式需求的干扰信息。

问题必须自然分布，不能写成明显给模型看的测试题。

## 7. 数据规模

- V1：30–40 条人工确认后的原子需求。
- 风险：15–25 项。
- 最终用例：80–120 条。
- 自动化决定同时覆盖四种结论。
- 至少包含人工功能、项目一可执行和通用自动化候选。
- V2：8–12 个需求变化。

## 8. 评估真值

评估真值与正常需求资料分开保存，至少包含：

- 评审问题 ID、类型、来源位置和关键语义。
- 必须识别的核心范围与风险。
- 必须覆盖的边界、状态和异常场景。
- V1→V2 的真实变化及预期影响资产。
- 不应错误建立追踪关系的干扰项。

真值不提供给正常模型调用。语义命中不要求逐字一致，最终评价由结构统计和人工抽查共同完成。

## 9. 结果输入设计

至少准备三份独立结果：

1. 人工功能测试结果：包含通过、失败、阻塞、未执行和执行异常。
2. 项目一兼容结果：包含结构化自动化结果和证据引用。
3. 其他自动化或补充复测结果：制造一次结果冲突和一次失败后复测通过。

所有执行编号、产品版本、需求版本、环境和时间均为合成内容。

## 10. 资产来源与隔离

- 每个文件进入 [资产来源清单](./asset-provenance.md)。
- 原创文件记录作者、日期、用途、需求版本和哈希。
- 公开标准或示例记录链接、许可证和改编范围。
- 工作经验总结只用于提炼通用分类，不进入需求包、Prompt、Mock 或真值。
- 不以“脱敏”方式复用任何真实需求、接口、缺陷和数据。

## 11. 生成顺序

1. 确定虚构产品名称、用户和边界。
2. 编写正常、完整的领域规则底稿。
3. 从底稿派生 V1，并植入已登记评审问题。
4. 创建页面截图和 OpenAPI，保证既有一致项也有计划冲突项。
5. 独立编写评估真值并隔离存放。
6. 设计 V2 变更及预期影响。
7. 生成人工、项目一和补充复测结果。
8. 计算哈希并更新来源清单。
9. 由人工复查不含真实公司标识、路径、协议和数据。

## 12. 验收

- 所有演示资产均有来源记录和哈希。
- V1、V2 和真值物理或逻辑隔离。
- 不出现真实公司、产品、人员、地址、接口、版本或缺陷数据。
- 资料足以支持完整页面流程和 80–120 条合理用例。
- 评审问题覆盖多种类型且能回指来源。
- 结果输入能验证复测、冲突、异常和多来源归集。
