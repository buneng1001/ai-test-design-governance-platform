# AI 测试设计与治理平台：面试项目介绍

## 一句话介绍

这是一个面向 Python 自动化测试工程师的 AI 测试左移与治理平台：它把多格式需求资料转化为可追踪的需求、风险、
测试用例和执行任务，再结合人工与自动化结果持续治理覆盖和回归范围。

## 为什么做这个项目

很多 AI 用例生成工具停留在“上传文档、生成一张表”。真正进入测试流程后，还会遇到来源不可追踪、风险不可解释、
模板不统一、AI 建议无人审核、需求变化后用例失效，以及人工和自动化结果无法统一治理等问题。

本项目重点解决的不是生成速度，而是如何让 AI 产物可审核、可修订、可发布和可持续维护。

## 核心流程

1. 导入文档、OpenAPI、JSON/YAML 或页面截图，形成不可覆盖的需求版本。
2. AI 提取原子需求并评审歧义、遗漏、冲突和不可测试条件，人工确认需求事实。
3. AI 分析测试范围、风险和自动化候选，系统按公开规则计算，人工确认最终设计。
4. 用户上传自己的多工作表 Excel 模板，平台按逐表字段映射生成用例。
5. 产品经理、测试经理和项目经理三个 AI 角色独立评审，人工逐条采纳或拒绝。
6. 用例文件可以单独下载；自动化用例可转换为通用 JSON/YAML 任务。
7. 导入人工结果、项目一结果和其他自动化结果，处理复测、异常和冲突。
8. 需求 V2 到来后分析影响，更新用例状态并生成回归候选，最终由人工确认。

## AI 用在哪里

- 原子需求提取和来源定位。
- 需求歧义、遗漏、冲突和可测试性评审。
- 测试维度、范围和风险建议。
- 自动化候选评价。
- 测试用例生成与内部设计依据。
- 产品、测试、项目三个角色的独立用例评审。
- 需求版本差异和变更影响建议。
- 缺陷模式与回归补充建议。
- 测试设计和治理报告摘要。

AI 不计算覆盖率、不生成执行序号、不决定测试通过失败、不修改历史事实，也不能越过四个人工确认关口。

## Python 自动化亮点

- FastAPI 提供清晰的领域 API。
- Python 解析 DOCX、PDF、OpenAPI、JSON、YAML、CSV 和多工作表 XLSX。
- JSON Schema 校验所有 AI 输出、测试任务和结果契约。
- 纯函数计算风险、自动化适用性、覆盖率和回归候选。
- Pytest 覆盖文件边界、状态迁移、版本追踪、适配器往返和异常导入。
- Mock AI 支持无密钥离线演示与 CI。

## 最值得讲的设计

### AI 建议与人工决定分离

模型只产生带来源和理由的候选项。需求、设计、用例和任务发布分别设置人工关口，所有采纳、拒绝和修改都有记录。

### 公司模板与内部模型分离

不同公司和部门的 Excel 模板可能完全不同。平台通过逐工作表字段映射适配外部格式，内部用稳定用例模型保存版本、
追踪和执行关系，避免模板变化破坏治理能力。

### 用例与执行记录分离

`TC-001` 表示测试定义，`TC-001-2` 表示第二次执行。失败、阻塞、执行异常和复测不会覆盖彼此，批次报告同时展示
初始结果、最新结果和人工确认结论。

### 任务与执行器解耦

平台先生成通用任务，再通过适配器转换项目一、Pytest 或其他执行器格式。项目一只是首个目标，本项目不是它的配置页。

## 与项目一的关系

项目一负责执行、证据采集、确定性检查和 AI 诊断；本项目负责执行前的测试设计和执行后的治理。两个项目可以分别演示，
未来通过版本化 JSON/YAML 契约形成闭环。

## 演示场景

演示使用完全虚构的智能采集设备需求包，包含设备状态、采集配置、存储、无线、控制页面、安全、异常恢复、性能、
稳定性，以及视频、音频、IMU 和同步等数据专项。V2 人为加入需求变化，用于演示影响分析和回归治理。

## 洁净重写声明

项目不包含原公司的代码、Prompt、页面、数据、文档或未公开信息。演示需求、接口、阈值、结果和评估真值均从零合成，
并通过资产来源清单记录创建方式、许可和哈希。

## 面试演示顺序

1. 展示 V1 需求资料和评审真值隔离。
2. 运行 Mock AI 需求评审并处理一个歧义。
3. 展示风险计算和自动化候选解释。
4. 上传一个多工作表 Excel 模板并生成用例。
5. 对比三个 AI 角色的不同建议，人工采纳其中一条。
6. 单独下载用例文件，并导出项目一 JSON/YAML 任务。
7. 导入三份结果，展示失败、执行异常、复测和冲突。
8. 导入 V2，展示影响路径、用例状态和回归选择。

## 当前边界

首版不生成完整可运行自动化代码，不控制设备或浏览器，不实现项目一检查器，不建设完整缺陷系统、多人权限、
在线协作或复杂 OCR。这些内容列入后续路线图，不作为首版成果表述。
