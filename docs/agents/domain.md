# 领域文档

本项目采用 single-context 结构。

## 开始工作前

- 阅读根目录 `CONTEXT.md`，使用其中定义的正式术语。
- 阅读 `docs/adr/` 中与当前工作相关的架构决策。
- 阅读根目录 `SPEC.md` 和当前任务引用的设计文档。
- 如果某个文件不存在，继续工作，不要为了补齐目录而提前创建空文档。

## 领域语言

任务标题、规格、测试名称和实现说明应使用 `CONTEXT.md` 中的正式术语，不使用其中 `_Avoid_` 列出的近义词。

如果需要的新概念尚未定义，应先判断是否真的属于本项目领域；确有缺口时，通过领域建模流程补充。

## ADR 冲突

如果计划或实现与现有 ADR 冲突，必须明确指出冲突及原因，不能静默覆盖原决定。

## 文档位置

- 领域词汇：`CONTEXT.md`
- 系统级架构决策：`docs/adr/`
- 正式项目规格：`SPEC.md`
