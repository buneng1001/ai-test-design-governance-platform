# AI 自动化全栈课程应用映射

## 1. 使用说明

本文件依据公开课程目录建立能力映射，不复制课程讲义、代码或未公开材料。状态定义：

- **计划**：规格已明确，尚未实现。
- **已实现**：功能已完成，但仍需补充验收证据。
- **已验证**：已有可复现测试、报告或演示证据。
- **不纳入首版**：与本项目定位不符或进入后续路线图。

当前项目处于设计阶段，以下首版内容默认均为“计划”。实现后必须将状态和证据链接同步到本文件。

## 3. 课程能力闭环

### 3.1 AI 辅助需求与用例

课程中的需求评审、范围分析、优先级、测试方法和 AI 用例审核，在本项目中形成一个可审计闭环，而不是单次对话：

`需求版本 → 原子需求 → 评审发现 → 范围 → 风险 → 用例 → 三角色评审 → 人工确认`

### 3.2 Python 自动化与工程化

Python 不只用于调用模型，还用于文件解析、Schema 校验、评分计算、追踪图、Excel 适配、任务契约、结果归集、
覆盖统计和回归规则。Pytest、Mock、CI 和报告用于证明这些结果可重复验证。

### 3.3 接口与数据驱动

JSON、YAML、OpenAPI、CSV 和 XLSX 同时承担需求输入、模板、任务和结果契约。平台用稳定内部模型隔离不同公司模板和
不同执行器格式，执行侧仍可使用参数化测试减少脚本重复。

### 3.4 面试表达

演示重点不是“AI 一键生成很多用例”，而是展示如何限制幻觉、保留来源、让三种视角独立评审、以确定性规则计算、
由人工作最终决定，并通过需求变更和执行结果持续治理。

## 4. 实现后更新规则

每完成一项能力，必须同时补充：

1. 状态从计划改为已实现或已验证。
2. 对应代码、测试、截图或报告的仓库链接。
3. 实际使用的合成数据规模和验证结果。
4. 若课程方法未采用，记录原因和替代方案。
5. 不得把后续计划标记为已完成。
