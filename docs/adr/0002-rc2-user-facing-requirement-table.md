# 用户以需求表和用例表为主要工作对象

## 状态

已接受，适用于 v0.1.0-rc.2。

## 背景

当前平台把解析片段直接展示为大量原子需求候选，并要求用户逐条确认。原子需求适合内部追踪，但不适合作为普通测试工程师的主要操作界面；同时，只有解析片段而没有语义分析结果，无法支持用户判断是否继续生成用例。

## 决策

用户界面以按模块分组的需求表和用例表为主。原子需求、稳定需求 ID、来源引用和审计记录继续保留在内部模型与详情页中。需求确认后才允许生成正式用例；生成后的用例支持编辑、移除和恢复。

## 取舍

这会增加需求归并、冲突识别、表格筛选和编辑历史的实现工作，但能把平台从“解析演示”提升为测试工程师可以判断和交付的工具。内部追踪模型不被删除，因此仍能满足版本、来源和审计要求。
