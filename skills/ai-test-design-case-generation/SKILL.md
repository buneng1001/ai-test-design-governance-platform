# AI 测试设计用例生成

本 Skill 是项目 v0.2.0 的候选用例生成规范来源。它只接受仓库内 `ai-test-design-requirement-analysis` 已完成 Step 07 的结构化交接；不读取工作区外的原始 Skill，不重新引入未选择需求，也不以固定业务示例或伪造成功结果替代模型输出。

它从本项目指定的外部用例生成方法派生，但已去除固定业务规则和按方法拆分文件的要求；外部原始目录不是运行时依赖。

## 输入与输出

- 输入是 `ai-test-design-workflow.v1` 的 Step 07 交接：分析运行 ID、软件版本、已确认测试点、关联稳定需求 ID 与规则 ID。
- 输出是可编辑的候选用例，而不是已确认用例或导出文件。调用 `validate_case_generation()` 后才可保存到平台现有候选用例模型。
- 每条候选必须显式保留：标题、测试目标、前置条件、测试输入、连续的操作步骤和逐步预期、整体预期、证据要求、设计依据、软件版本、P0～P3、稳定需求 ID、测试项 ID、Step 07 测试点编号和平台测试点 ID。
- 测试方法属于设计依据；不同边界值、等价类或场景应形成可独立追踪的候选用例。

## 追溯与失败处理

候选用例只能引用同一分析运行中已确认的测试点，且平台测试点 ID、测试项 ID、软件版本和稳定需求 ID 必须与交接映射一致。候选编号唯一；步骤从 1 连续递增；每一步必须有可验证预期。

信息不足时返回 `needs_information` 和缺失项，模型失败时返回 `failed` 和失败代码。这两种状态不得返回候选用例，也不得显示为成功。需要回退时，回退产物仍使用同一契约并明确其来源，由后续工作流决定是否保存。

## 兼容策略

输入和输出必须携带同一 `contract_version`；输出还须记录 Prompt 与模板版本。改变必填字段语义、ID 映射或状态含义时升级主版本；只新增可选字段时保持旧产物可读。Prompt、模板和模型版本的变化不得无版本标记地改变历史候选用例的解释方式。
