# AI 测试设计需求分析

本 Skill 是项目 v0.2.0 的需求分析规范来源。它只处理已登记的需求资料、来源定位和人工确认状态；不读取工作区外的原始 Skill，不访问未登记材料，也不生成详细测试用例、操作步骤或具体预期。

它从本项目指定的外部需求分析方法派生，但已裁剪为平台领域术语、结构化产物和确定性校验；外部原始目录不是运行时依赖。

## 输入与边界

- 输入包含测试对象、软件版本、需求资料版本、可解析材料、来源定位和当前恢复点。
- 只有已确认需求可进入正式测试点；待确认内容应保留为建议或信息缺口。
- 全部输出使用 `ai-test-design-workflow.v1`，并先通过 `backend/app/workflow_contracts.py` 的 `RequirementAnalysisRun` 校验后才可交给后续流程。
- 使用 P0、P1、P2、P3 四级优先级。P3 只适用于低风险、低频或罕见场景，不能因低概率掩盖资金、数据、安全或可用性损失。

## Step 00～08

| 阶段 | 依赖 | 结构化产物 | 失败边界 |
| --- | --- | --- | --- |
| S00 | 已登记材料与版本 | 材料基线、内容定位、解析诊断 | 无可用材料时标记 `needs_information` |
| S01 | S00 | 功能识别与模块 | 材料无法支持识别时停止 |
| S02 | S01 | 业务规则、语义需求、验收条件与来源 | 事实与推导分开标记 |
| S03 | S02 | 正常场景方向 | 不补造需求事实 |
| S04 | S02 | 异常场景方向 | 缺少异常规则时列入信息缺口 |
| S05 | S02 | 边界条件方向 | 阈值不明必须待确认 |
| S06 | S02～S05 | 隐性风险与权限方向 | 推导必须保留依据 |
| S07 | S02～S06 | 测试项、测试点、来源和规则映射 | 测试点只表达“测什么” |
| S08 | S07 | 覆盖自检、孤立项和盲区 | 不通过时不得宣称可生成用例 |

阶段从 S00 连续执行；`needs_information` 或 `failed` 是终止状态，不能产生后续成功产物。每个 S07 测试点必须包含 `S07-TP-*` 阶段编号、平台测试点 ID、测试项 ID、稳定需求 ID、适用方向和目标。阶段编号与平台 ID 不要求字面相同，但映射必须显式、唯一且可反查。

## 与用例生成的交接

只有已完成 S07 的分析运行才能调用 `step07_handoff()`。交接内容为确认测试点、稳定需求 ID、规则 ID 和软件版本；详细步骤、输入和预期由 `ai-test-design-case-generation` 生成。

## 兼容策略

已保存产物须带 `contract_version`、输入版本、输出版本、Prompt 版本和模板版本。破坏字段含义、阶段顺序或追溯规则时创建新的主版本；仅新增可选字段时保持兼容并由适配器归一化。不得以更新 Prompt 或模板的方式静默重解释历史产物。
